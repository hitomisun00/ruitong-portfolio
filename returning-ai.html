Project 01 · 2025 · Product + System Design

Store Redesign

The loyalty store let traders browse and claim rewards — but the system underneath couldn't scale. I redesigned it end to end: redemption logic, a permission framework, reward status management, and a cleaner category structure. This is system design as much as it is UI.

My scope I owned the product planning, system logic, and full UI — from the redemption-methods architecture and eligibility rules to every admin panel and trader-facing screen. Only the backend code was written by engineering.
Project summary — before vs after
At a glance

One store, rebuilt from the logic up

The redesigned store keeps the familiar browse-and-claim surface but adds the layer that was missing: a configurable system for how rewards are claimed, who can claim them, and what state each redemption is in.

The challenge — what was wrong with the old store
The problem

No logic layer, no control

Traders could claim rewards, but there was no system for fulfilment — physical delivery, in-app credits, gift codes all had to be hacked in per client. Brokers had no way to gate rewards behind eligibility, and reward states were ambiguous once claimed.

Project 02 · Product + System Design · Mini-Games

Two reward tiers: correct winning team, and a bigger payout for the exact score.

Project 03 · Featured · AI-Assisted End-to-End Product Creation

Quiz Log & Quiz Analytics

A complete product — built end to end with an AI-assisted, multi-agent workflow. From the problem and a planning doc, through architecture and local development, to a shipped quiz logging system and an analytics dashboard. I drove every layer: product, UX, system, and implementation logic.

Why it's featured · no Figma This is the clearest example of how I work now. There were no Figma designs — I briefed the feature in plain language with reference screenshots, planned it with Codex sub-agents, built it locally, then ran a PM · UX/UI · Dev · QA agent review on localhost before a human dev did the final code review and backend refinement. Design and engineering collapse into one loop.
The problem — why logs & analytics were needed
The gap

Quizzes ran blind

Brokers were running quiz games but had no visibility into what happened — who played, what they answered, how the quiz performed. There was no log to audit individual activity and no analytics to read engagement at a glance.

Two surfaces close the gap: a log to audit every play, and an analytics view to read engagement at a glance.
